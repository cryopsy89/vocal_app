## 0. Что делает Phase 3

Собирает ПОЛНЫЙ путь оценки: из target-вокала строит целевую мелодию, выравнивает
пользовательский дубль по времени и считает score. Это самая рискованная часть
проекта (сегментация нот + alignment, бриф п.6 и п.8).

Три блока:
1. **Сегментация нот** (`notes.py`) — f0 → стабильные целевые ноты
2. **Alignment** (`align.py`) — DTW-выравнивание user к target по времени
3. **Сборка** (`pipeline.score_take`) — полный путь + `test_phase3.py`

## 1. ПЕРЕОСМЫСЛЕННАЯ постановка (важно)

Кейс Виктора: файл, который он дал — это его СТУДИЙНЫЙ вокал, который он считает
**идеалом (target)** для песни. «Что спел» = НОВЫЙ живой дубль под минус (запишет отдельно).

Следствия:
- target и user — **ОДИН голос** → транспоз НЕ нужен (нет чужой тональности);
- **align (DTW) нужен** — живой дубль не совпадёт со студийным по времени;
- это заменяет исходную идею «извлекать мелодию из чужого оригинала».

## 2. Сегментация нот (notes.py)

Превращает дёрганый f0 в стабильные ноты, чтобы вибрато не плодило десятки нот.

### Пайплайн сегментации
1. `reject_outliers` — выкинуть октавные срывы трекера (отскок > `outlier_semitones`=6
   полутонов от локальной медианы). До сглаживания, иначе центр ноты уедет.
2. f0 → полутоны → `median_smooth` окном `smooth_ms`=200 мс.
3. Сегментация с **гистерезисом по времени**: смена ноты подтверждается только если
   новый уровень держится ≥ `note_min_ms` (иначе это качание вибрато / проходящий тон).
4. Короткие сегменты (< note_min_ms) отбрасываются как украшения.
5. Центр ноты = медиана по ОЧИЩЕННОМУ контуру.

### Реальный баг, найденный на студийном вокале (для истории)
**v1** (smooth 120 мс, порог смены 0.7 полутона) → **75 нот/30с**: раздробил вибрато
(G3-F#3-G3-F#3 = одна нота с вибрато, разрезанная на 5), потому что порог смены был
МЕНЬШЕ размаха вибрато. **v2** (smooth 200 мс ≥ период вибрато ~180 мс; порог 1.0
полутон + гистерезис) → **42 музыкальные ноты/30с**, длительности медиана 355 мс.

### Честный остаток (НЕ баг, принципиальный предел)
Быстрые спуски всё ещё дробятся на короткие ступеньки. Граница «отдельные ноты vs
глиссандо» объективно размыта без знания задуманной мелодии. Виктор согласился
оставить как есть (универсальную сегментацию «под все песни» не отстроить).
Смягчающий фактор: **target и user сегментируются ОДНИМ кодом**, поэтому
систематическая ошибка сегментации частично сокращается.

### Ключевые функции
- `segment(f0)` → список `Note(start, end, hz, semitone, name)`.
- `notes_to_target(notes, n)` → плоские ступеньки. **ТОЛЬКО для note-вердикта и UI!**
- `prepare_contour(f0)` → отброс выбросов + сглаживание. Применять ОДИНАКОВО к user и target.
- `smoothed_target(f0, notes, n)` → **сглаженный контур для расчёта центов** (см. §4).
- `vibrato_frame_mask(...)` — существует, но НЕ используется (см. §4, вибрато).

## 3. Alignment (align.py) — DTW

Выравнивает user к target по ВРЕМЕНИ, чтобы задержка вокала не стала кучей ложных
pitch-ошибок (бриф п.8).

### Метод
- DTW по контуру **полутонов** (не waveform, не MFCC).
- **Sakoe-Chiba band АБСОЛЮТНЫЙ** (`dtw_band_ms`=700), НЕ доля длины (см. баг §5).
- unvoiced-vs-unvoiced = стоимость 0; voiced-vs-unvoiced = штраф (`dtw_unvoiced_penalty`=4).
- `warp_user_to_target` мапит user на сетку target; если один target ↔ несколько user
  — медиана.
- `align_confidence(norm_cost)` → 0..1, идёт в C_align.

### КРИТИЧНО: де-меанирование (см. баг §5)
Путь ищется по ДЕ-МЕАНИРОВАННЫМ контурам (у каждого вычтена своя медианная высота).
DTW матчит по ФОРМЕ мелодии, а warp применяется к ИСХОДНОМУ user.

## 4. КРИТИЧНОЕ решение: target для scoring = СГЛАЖЕННЫЙ КОНТУР

**Самый важный вывод Phase 3. Не сломать.**

f0_target для РАСЧЁТА ЦЕНТОВ = сглаженный контур эталона (`smoothed_target`),
НЕ плоские квантованные ступеньки-ноты.

Почему: плоский центр ноты против живого контура штрафует естественный дрейф/вибрато.
Копия-vs-копия на плоских ступеньках упиралась в потолок **83%**. Сглаженный контур
(форма-против-формы, ОБА прошли `prepare_contour`) → копия-vs-копия **100%**, а
реальная фальшь -60c всё равно даёт p50=0%/bias -60c (метрика осталась строгой, не
просто раздута).

Ступенчатые ноты (`notes_to_target`) остаются ТОЛЬКО для note-вердикта и UI-блоков.

**Вибрато:** ранний план был маскировать вибрато-фреймы. Провалился — порог 20c
пометил 64% фреймов как «вибрато» и сделал p50 ХУЖЕ (обычная микронестабильность
голоса — не вибрато). Заменено сглаженным target: сглаживание обоих сторон гасит
вибрато без явной маски. Когда target сглаженный — внутреннюю vibrato_mask НЕ включать
(она пометит весь контур и обнулит счёт); передавать `vibrato_mask_ext=zeros`.

## 5. Два бага alignment, найденных тестами на реальном вокале

### Баг A: DTW маскирует систематический pitch-сдвиг
Тест `-60c flat` показывал bias **-4c** вместо -60c. DTW пересопоставлял чужие ноты
по высоте, чтобы сблизить контуры — и «съедал» фальшь. Это фундаментальная ловушка
DTW по абсолютной высоте (align компенсирует высоту временем).

**Фикс:** де-меанирование (§3). DTW ищет путь по ФОРМЕ (относительным ходам), warp
применяется к исходному user → систематический сдвиг сохраняется для scoring.
**Принцип: align судит ФОРМУ, scoring судит АБСОЛЮТНУЮ высоту. Разделение этих ролей
— то, что делает систему честной.**

### Баг B: band как доля длины
`band_frac=0.25` от 20с = 5 секунд коридора → DTW гулял на секунды и пересопоставлял
ноты. **Фикс:** band в абсолютных мс (`dtw_band_ms`=700).

## 6. Полный путь — pipeline.score_take

```
score_take(f0_target_raw, f0_user_raw):
  1. segment(target) -> ноты (для note-вердикта и UI-границ)
  2. smoothed_target(target) -> сглаженный контур для расчёта центов
  3. prepare_contour(user) -> тот же препроцессинг (форма-с-формой)
  4. warp_user_to_target (DTW, де-меанированный) -> user выровнен по времени
  5. compare.analyze(vibrato_mask_ext=zeros) -> Result
  # транспоз НЕ делается (один голос)
```

|------|-----------|
| ideal vs ideal | p50=**100%**, notes 42/42 |
| shift 300ms +align | p50=**100%** (DTW убрал задержку) |
| flat -60c error | p50=**0%**, bias -60c, 0/42 (поймано, НЕ замаскировано) |
| half -70c | p50=39%, bias -52c (локализовано) |

## 9. Инварианты Phase 3 (НЕ сломать — критично)

- **target для scoring = сглаженный контур, НЕ плоские ступеньки.** Ступеньки только UI/вердикт.
- **user и target проходят ОДИН prepare_contour** (форма-с-формой).
- **DTW на де-меанированных контурах**, warp на исходном user. align=форма, scoring=высота.
- **DTW band абсолютный** (мс), не доля длины.
- Когда target сглаженный — внутреннюю vibrato_mask НЕ включать (vibrato_mask_ext=zeros).
- reject_outliers ДО сглаживания, иначе центр ноты уедет.
- Сегментация target и user — одним кодом (сокращает систематику).
- Транспоз в кейсе одного голоса НЕ нужен; если появится — ДО align.
