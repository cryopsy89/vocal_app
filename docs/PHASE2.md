## 1. Выбор трекера — ПЕРЕСМОТРЕНО (важно)

В Phase 0 фиксировали pYIN+CREPE. В Phase 2 сделали currency-check (бенчмарк
сентября 2026) и **сменили решение**. Причина: pYIN оказался аутсайдером.

Бенчмарк lars76/pitch-benchmark (12 алгоритмов, 8 датасетов):

| Трекер | Ср. точность | Вокал | Confidence | Лицензия | Apple Silicon |
|---|---|---|---|---|---|
| **SwiftF0** ← выбран | 90.2% (1) | 95% MIR-1K | да, из коробки | MIT | CPU 450x RT |
| RMVPE | 87.2% | лучший на пении, устойчив к фону | да | смешанная (в RVC) | тяжелее |
| CREPE | 85.3% | 95.7% | да | MIT | MPS/медленный |
| pYIN | 78.7% (посл.) | слабо | да | ISC | CPU |

**Решение: SwiftF0 для чистого пользовательского вокала.**
- точнее всех, MIT (коммерция ок);
- **CPU-only на 450x realtime** — снимает ВСЮ проблему Apple Silicon/MPS: не нужен
  ни torch, ни GPU. Это ключевой аргумент.
- per-frame confidence из коробки → прямо кормит наш gate;
- `pip install swift-f0`, ONNX 135 КБ, диапазон G1–C7.

**RMVPE** — резерв для ГРЯЗНОГО извлечённого оригинала (сделан под вокал в
полифонии, arxiv 2306.15412, устойчив к leakage). Проверять живьём, если понадобится.
В текущем кейсе Виктора (студия vs живой дубль, один голос) — НЕ нужен.

Оговорка честности: бенчмарк написан автором SwiftF0. Цифры на публичных
датасетах воспроизводимы, а MIT+CPU+confidence — факты из первоисточника.

**Трекер — сменная деталь за интерфейсом compare (f0 + confidence массивы).**
Смена трекера не трогает scoring-код.

## 2. pitch.py — обёртка SwiftF0 + генератор wav

### Реальный API SwiftF0 (проверено, не по докам)
`detector.detect(wav, sr)` → `PitchResult` с полями:
- `pitch_hz` (f0 по фреймам), `confidence` (0..1), `timestamps` (сек), `audio`.
- **`voicing` НЕТ** — voiced/unvoiced выводим САМИ из confidence (порог 0.5, README).
- Сетка **~16 мс** (0.016с шаг), НЕ наши 10 мс. Ресэмплинг — в pipeline.

### Функции
- `synth_wav(f0_frames, sr, n_harmonics=5)` — waveform из известного f0. Гармоники
  1/k (ближе к голосу, чем чистый синус), непрерывная фаза (интеграл частоты, без
  щелчков на стыках). Нужен для проверки трекера на честной ground truth.
- `track(wav, sr, voiced_thr=0.5)` → `(f0_hz, confidence, timestamps)`.
  f0=NaN где confidence<порог. Сырой выход трекера (сетка ~16 мс).
- `hz_to_cents_error(tracked, true)` — оценка ошибки САМОГО трекера в центах.

## 3. Проверка трекера (test_phase2.py, 5/5)

Генерим wav из известного f0 → гоним SwiftF0 → меряем сколько врёт. Результаты:

| Тест | Результат |
|------|-----------|
| steady note A4 | ошибка **4.5c** |
| диапазон G2–C6 | **0.6–6.9c** на всех высотах |
| follows -100c offset | трекер вернул смещение (1.3c), НЕ подтянул к «правильной» |
| no octave slips | 0 срывов на ровной ноте |
| silence → unvoiced | conf ~0.99 на ноте vs ~0.00 в паузе |

**Вывод: ошибка трекера 0.6–6.9 центов — в разы меньше нашего порога ±25c.**
Трекер не съест интонацию. Главное — на -100c он вернул именно -100, не маскирует фальшь.

### Реальный вокал (sanity-check)
Виктор прогнал Demucs на своей студийной записи «90 белых дней», отдал vocals.wav.
SwiftF0 на 30с-фрагменте: чистый связный контур C3–C4, voiced-confidence 0.86,
gate корректно пометил 2-3 мусорных выброса у C5/C6. **Главный риск Phase 2
(трекер разваливается на реальном аудио) — снят.**

## 4. Интеграция — pipeline.py (ресэмплинг + end-to-end)

### Ресэмплинг сетки (16 мс → 10 мс) — НЕТРИВИАЛЕН
`resample_f0(f0_src, ts_src, dur_s)`:
- **f0 нельзя интерполировать линейно через границы voiced/unvoiced** — между 200 Гц
  и NaN линейная интерполяция даст мусор на переходе.
- Решение: интерполируем в **ЛОГ-области (полутоны)** — слух логарифмичен, корректно.
- voiced-маску переносим **ОТДЕЛЬНО**: целевой фрейм voiced только если он в пределах
  ~1.5 фрейма трекера от реальной voiced-точки (не «дотянут» из тишины).
- `resample_confidence` — ближайшим соседом (это вероятность, не частота).

### Функции
- `wav_to_f0_grid(wav, sr)` → (f0, conf) на сетке 10 мс. Готово для compare.
- `analyze_wavs(...)` — END-TO-END (транспоз/align НЕ здесь, они между Phase 3 и этим).
- `score_take(...)` — ПОЛНЫЙ путь Phase 3 (см. PHASE3.md).
- `load_wav_mono(path, start_s, dur_s)` — чтение wav/mp3 → mono float32.

### Проверка (test_integration.py, 5/5)
Генерим wav из известного f0, гоним весь конвейер, сверяем центы:

| Тест | Результат |
|------|-----------|
| -100c offset сквозь конвейер | bias **-101.3c** (прошло почти точь-в-точь) |
| +40c | p50=100% (в ±50), p25=0% (не в ±25) — пороги работают |
| multi-note | обе -60/-70c ноты → low |
| пауза не протекает при ресэмплинге | 0 фреймов через паузу |
| perfect | bias +4.5c |

## 5. Задокументированный floor (НЕ заглушка)

На идеальной синтетике полный конвейер даёт **~+4.5c bias** (собственный джиттер
SwiftF0 ~4-5c + микропогрешность ресэмплинга). Ниже порога ±25c, безвреден, но:
**конвейер НЕ битово-точный, реальный голос шумнее.** Это предел трекера, не баг.

## 8. Инварианты Phase 2 (не сломать)

- Трекер за интерфейсом (f0+confidence). Смена трекера не трогает compare.
- SwiftF0 не отдаёт voicing — выводить из confidence (порог 0.5).
- Сетки разные (16 vs 10 мс) — ресэмплинг обязателен, в ЛОГ-области, voiced-маска отдельно.
- f0 никогда не интерполировать линейно через unvoiced.
- Floor ~5c существует — не считать конвейер битово-точным.
- Веса моделей — только на машине пользователя (сеть инструментов в аллоулисте).
