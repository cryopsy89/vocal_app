# Vocal Pitch Accuracy Analyzer

Локальный инструмент: оценивает, насколько точно спетый вокал попадает в ноты
относительно эталонной мелодии, в центах. Не автотюн, не визуализатор — выдаёт
объективную оценку «попал на N%» и список конкретных промахов.

## Статус

Готова аналитическая часть (Phase 1–3): извлечение f0, сегментация нот,
выравнивание по времени (DTW), расчёт точности. UI (Phase 4) добавлен;
training-режим (Phase 5) ещё не сделан.

Тесты: **39 тестов**, проходят через `pytest` и прямым запуском (см. ниже).
Phase 3 требует фикстуру `tests/data/studio_f0.npz`; без неё эти 4 теста
пропускаются (skip), не падают.

Проверено на реальном материале: студийный вокал (эталон) vs живой дубль под
минус — конвейер отрабатывает, честно ловит промахи и не выдаёт цифру там, где
оценивать нечего (пустой вход / мизерное покрытие → LOW CONFIDENCE).

## Установка

```bash
pip install -r requirements.txt
```

`soundfile` требует системную `libsndfile`. Source separation (Demucs) ставится
и запускается ОТДЕЛЬНО на машине пользователя — см. requirements.txt.

## Структура

```
src/                исходники (один пакет, взаимозависимые модули)
  config.py           все калибруемые пороги
  synth.py            генератор f0 с известной ground truth (для тестов)
  compare.py          формула scoring (центы, p25/50/100, coverage, confidence)
  pitch.py            обёртка SwiftF0 + генератор wav из f0
  notes.py            сегментация нот, сглаженный target, отброс выбросов
  align.py            DTW-выравнивание по времени (де-меанированное)
  pipeline.py         сборка: wav -> f0 -> resample -> align -> score
tests/              тесты + tests/data/ (фикстуры)
docs/               PHASE1.md, PHASE2.md, PHASE3.md — история решений и обоснования
requirements.txt
```

Фазы (P1 формула, P2 трекинг+интеграция, P3 сегментация+align+scoring) — это
история разработки, задокументированная в `docs/`. В файловой структуре фаз нет:
код — единый связный пакет.

## UI (Phase 4)

```bash
streamlit run app.py
```

Загружаешь эталонный вокал-wav и свой дубль (готовые вокал-дорожки, без минуса —
отделение делается отдельным шагом до загрузки), опционально задаёшь участок по
таймкодам, жмёшь «Оценить». UI показывает крупно p50, рядом coverage/confidence/
ноты/worst с таймкодами, снизу — вспомогательный deviation-график. При ненадёжной
оценке (мало данных, плохое выравнивание) вместо процента — LOW CONFIDENCE.

Вся логика оценки — в `pipeline.score_wavs`; `app.py` только рисует. Separation
(Demucs) остаётся ручным шагом на машине пользователя.

## Как это работает (кратко)

1. Из эталонного вокала извлекается f0 (SwiftF0, CPU-only, MIT).
2. Сегментация в ноты + сглаженный контур-target.
3. Пользовательский дубль: тот же f0 + препроцессинг.
4. DTW выравнивает дубль к эталону по ВРЕМЕНИ (по форме мелодии, не по абсолютной
   высоте — иначе align маскирует систематический pitch-сдвиг).
5. Scoring в центах: главная цифра p50 (доля времени в ±50c), рядом coverage и
   confidence. Ненадёжный результат → LOW CONFIDENCE, а не красивый процент.

Подробности решений и обоснования — в `docs/PHASE{1,2,3}.md`.
